# 技术方案：从原始视频到 KA-GZSL 分类

## 1. 正确的接入位置

这是“特征提取 + 已训练分类模型 + 展示服务”，不是在分类器前随意拼接一个网络。实际固定源码为 `pointerHu/KA-GZSL@085eae46195728fef3ad86b7a046528913f9bc39`。

```text
视频文件
  ├─ OpenCV 中间帧 → CLIP ViT-B/32 → L2 归一化视觉向量 [1,512]
  └─ 音轨 → librosa 32kHz 单声道 → 中心10秒/右侧补零
                            → WavCaps HTSAT-BERT + audio_proj → 归一化 [1,1024]
                  ↓
           原 KA-GZSL.get_embeddings
                  ↓
           64 维视频语义表示
                  ↔
  配对类别向量 [C,1536] → 原模型 W_enc / W_proj → 类别原型 [C,64]
                  ↓
       距离匹配 + stage-A验证集确定的已见类偏置
                  ↓
       argmax 类别 + softmax 相对置信分数 + Top-5
```

冻结 CLIP、WavCaps 和 KA-GZSL 的权重，推理时全部 `.eval()`，不会在一次用户上传时重新训练模型，也不会让样本标签参与预测。

## 2. 编码器必须与训练特征同分布

当前模型使用的是 512+1024 维接口。**维数相同仍不保证语义坐标系相同**。因此不能把另一个 CLAP 的向量补零/线性拉伸成 1024 维，也不能以零向量替代缺失的音频。

WavCaps 的 `ASE.encode_audio()` 包含音频编码器和 `audio_proj`，最终归一化输出 1024 维。仅拿 HTSAT 中间层的 768 维表示不等价。展示服务只构造 ASE 的音频分支，严格加载 `audio_encoder.*` 与 `audio_proj.*`，不会额外下载训练时初始化用的 HTSAT.ckpt 或用于固定类别文本的 BERT。类别文本向量直接从与 checkpoint 配对的数据包导出。

官方同形权重也可能来自不同微调版本。本代码可检查键、维度和 SHA256，但**不能仅靠网络结构证明与已有特征文件来自同一个模型版本**；应进一步取得同一个原始视频和已有特征进行逐样本比对。当前不宣称这一步已完成。

## 3. 必须记录的历史预处理问题

固定仓库的 UCF 提取脚本从 OpenCV 读取 BGR，存入取值约 0..255 的 float32 Tensor，再交给 `ToPILImage()`。该转换对 float Tensor 会先乘 255，再转换成 uint8；它与常规 BGR→RGB 的 uint8 图像路径不同。

本项目提供两种**明确命名**的配置：

- `legacy`（默认）：逐字遵循固定脚本的中间帧颜色/数值转换，避免未经验证就改变特征分布。
- `rgb`：常规 RGB 图像处理，用于单独实验，不可直接宣称复现旧特征。采用它作为正式输入流程前，需要检查特征一致性，必要时重新提取训练特征并训练下游模型。

保存 `preview.jpg`（正常颜色预览）和 `model_input.jpg`（实际送入 CLIP 的图像）供核对。长音轨中心裁剪至 320000 个采样点，短音轨在右侧补零，和脚本的 10 秒逻辑一致。音轨解码使用 PCM16 再由 librosa 重采样；容器/原始位深和解码库版本仍可能引入小差异，需要配对数据量化。

当前实现不悄悄增加多帧平均、时间 Transformer 或片段投票。它们可以是后续视频鲁棒性改进实验，但更换聚合方式需要单独验证，不能混入“原模型复现”。

## 4. 分类与相对置信分数

对候选类 c，令 d_c 为原模型输出与文本原型的 L2 距离，b 为验证集确定的已见类偏置：

```text
logit_c = -d_c - b × I(c 是已见类)
p_c = exp(logit_c / T) / sum_j exp(logit_j / T)
prediction = argmax_c p_c
```

GZSL 候选集合为导出数据划分的已见类与未见类并集，ZSL 只包含该划分的未见类，**不是整个 UCF101 的所有类别，更不是任意开放词汇**。类别名、索引、seen mask 与文本向量一起导出，避免使用文件夹遍历顺序错配。

T=1 时分数未做概率校准。提高或降低温度只改变分数锐度，不能制造模型更准确的事实。不能把 `max(p)` 当作该预测正确的真实概率。

校准扩展应在未参与训练和最终测试的校准集合上拟合温度，在独立留出集合报告 NLL、ECE、Brier 等指标。阶段 A 的温度能否转移给阶段 B 也需评估。提供的脚本仅拟合/记录温度，不作“已经校准”的承诺。

当前不含经过验证的 OOD/未知类拒识器。低分和小间隔可作为人工复核提示，但不能据此自动证明“未知类”。

## 5. 后续研究型扩展

先补齐严格匹配的编码器权重，并对配对视频/已有特征计算最大绝对差、余弦相似度和类别一致率。接着在独立原始视频验证集测量真实准确率和校准误差。完成后再评估多帧/多片段聚合、无音轨独立视觉模型、经过验证的未知类拒识，以及每个数据集对应的正式模型包。
